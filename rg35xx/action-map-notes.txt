ACTION MAP - REPOSITORY BINARY ANALYSIS

Scope and notation
------------------
One row per archived CMD/BAS program (27 rows), using app.name as its title.
RetroStore Client and Dancing Demon are included for archive coverage, although
one is a utility and the other a music/dance application. DOS/tutorial entries
without a standalone CMD/BAS are excluded. Generated LAUNCH/CMD is not a game.

The CSV is now also the manually edited custom-mapping source. The builder
ignores empty and lowercase x cells; other cells assign RG35XXPRO controls.
The analysis below describes the identified TRS-80 actions, independently of
which controls are currently assigned. See rg35xx-control-mapping.md.

An x means the input has an identified role in at least one game/menu phase.
Columns are physical TRS-80 keys. UP/DOWN/LEFT/RIGHT mean the arrow keys, not
ASCII bracket characters. SPACE is the spacebar. COMMA/PERIOD/SEMICOLON name
unshifted physical keys; SHIFT is explicit where needed. A+B means press keys
simultaneously, never a sequence. Context-dependent meanings are recorded below.

ANY_KEY denotes a genuine any-key prompt rather than pretending that every
letter has a separate game action. TEXT_INPUT denotes free-form name/password
or editor input. NUMERIC_INPUT denotes variable-length numeric parameters.
Dedicated letter/number columns cover named commands/options or code-entry
buttons, not every character accepted in a name field. BASIC BREAK is interpreter
stop, where indicated. Disk I/O retry prompts, debugger controls, joystick ports
without keyboard equivalents and hardware RESET are not game action columns.

Multi-key columns cover distinct gameplay movement/fire/modifier combinations
using canonical arrow/SPACE controls, tank track chords, and explicit reset/
pause chords. Equivalent single-key aliases are included, but their Cartesian
products are not duplicated (e.g. COMMA+F is an alias of LEFT+SPACE in COSMIC).
Likewise this is not an enumeration of arbitrary supersets such as start+fire,
all menu commands held together, or every secondary command with every move.
Opposing directions are not assumed to work merely because both bits can be set.
Blank cells mean no independently identified action in this action vocabulary;
they are not a proof that a key can never affect any hidden/error/cheat state.

Evidence method
---------------
Parsed CMD load records into 64 KiB memory maps, disassembled Z80 code with
z80dasm, followed direction/fire masks and branch precedence, and inspected
embedded text and repository screenshots. Followed startup relocations where
needed. Robot Attack's loader additionally complements its code/data: that
transformation was applied before inspecting it. Runtime memory snapshots in
sdltrs corroborated Robot Attack and Defense Command's relocated/decrypted
input routines and several title screens. Tokenized BASIC was inspected for
INKEY$, INPUT, PEEK and USR paths; bytes inside Dancing Demon's binary REM
payload were not blindly counted as executable keyboard code.

Keyboard matrix used to decode addresses (hex; bits increase left to right):
  3801: @ A B C D E F G
  3802: H I J K L M N O
  3804: P Q R S T U V W
  3808: X Y Z (remaining positions unused on standard keyboard)
  3810: 0 1 2 3 4 5 6 7
  3820: 8 9 : ; , - . /
  3840: ENTER CLEAR BREAK UP DOWN LEFT RIGHT SPACE
  3880: SHIFT (Model III also has a separate right-SHIFT bit)

Addresses below are hexadecimal and refer to the CMD load map unless explicitly
labeled runtime. Loader relocation can make an address in the file differ from
the address where that instruction executes. Metadata is supporting evidence,
not a substitute for the code: the Donkey Kong shortcut discrepancy is noted.
This is a static/control-flow inventory with targeted emulator checks, not an
end-to-end playtest of every action in every game phase.
